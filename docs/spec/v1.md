# v1 规格说明

## 范围

本版本新增受控 label 管理能力。

- label 不再只是 issue front matter 中的自由文本
- 系统新增独立的 label registry
- 所有 label 统一标准化为大写
- `new` 和 `modify-metadata` 默认禁止直接引入未注册 label
- 新增 `labels` 命令族用于查看、同步、删除和重命名 label

## 目标

本版本的目标是把 label 从松散字段升级为受控 metadata：

- 保证所有 label 的大小写一致
- 保证 issue 中使用的 label 默认来自统一 registry
- 提供显式命令维护 label 生命周期
- 为后续基于 label 的查询和自动化提供稳定基础

## 数据模型

在 issue base dir 根目录下新增独立文件 `labels.json`。

示例：

```json
{
  "labels": ["AUTH", "BUG"]
}
```

约束：

- 文件路径为 `{issueBaseDir}/labels.json`
- 文件格式为 JSON
- 顶层结构为对象，包含字段 `labels`
- `labels` 为字符串数组
- 所有 label 在写入前统一做 trim 和大写标准化
- registry 中的 label 必须唯一
- 写回文件时应去重

## Issue 数据约束

issue front matter 中的 `labels` 字段继续保留为数组，但从本版本开始遵守以下规则：

- 所有 label 一律以大写形式存储
- 默认情况下，issue 中出现的每个 label 都必须存在于 `labels.json`
- 不允许通过普通写命令静默引入 registry 之外的新 label

## 新增命令

### `labels`

输出 registry 中的全部 label。

行为：

- 读取 `{issueBaseDir}/labels.json`
- 若文件不存在，则按空集合处理
- 输出前按字母排序
- 每行输出一个 label

用途：

- 查看当前系统中受控的全部 label

### `labels sync`

全量扫描 issue base dir 下的所有 issues，并同步 registry。

行为：

- 扫描所有 issue front matter 中的 `labels`
- 将扫描到的 label 统一标准化为大写
- 若 issue 中存在小写或混合大小写 label，则同步回写 issue 文件
- 将扫描到但 registry 中不存在的 label 补入 registry
- registry 最终写回为去重后的大写集合

用途：

- 从历史 issue 数据回填 registry
- 收敛历史大小写不一致问题

## 新增子命令

### `labels remove --label <LABEL>`

从 registry 中删除指定 label。

默认行为：

- 先将输入值做 trim 和大写标准化
- 检查是否有 issue 正在引用该 label
- 若 label 不存在于 registry，则失败
- 若存在 issue 引用，则失败
- 若不存在引用，则从 registry 中删除该 label

带 `--force` 时：

- 即使仍有 issue 引用，也允许继续执行
- 从 registry 中删除该 label
- 同时从所有引用该 label 的 issue 中移除该 label

### `labels rename --from <OLD> --to <NEW>`

重命名 registry 中的 label，并同步更新所有 issues。

默认行为：

- `OLD` 和 `NEW` 都先做 trim 和大写标准化
- 若 `OLD` 不存在于 registry，则失败
- 若 `NEW` 已存在于 registry，则失败
- 否则将 registry 中的 `OLD` 替换为 `NEW`
- 将所有 issues 中的 `OLD` 同步替换为 `NEW`

带 `--force` 时：

- 允许 `NEW` 已存在
- 该场景语义为 merge
- 所有 issues 中的 `OLD` 都替换为 `NEW`
- registry 中删除 `OLD`
- registry 中保留 `NEW`

## 现有命令变更

### `new`

新增 flag：`--allow-new-label`

默认行为：

- 命令接收到的每个 label 都先做 trim 和大写标准化
- 若任一 label 不存在于 registry，则命令失败

带 `--allow-new-label` 时：

- 允许将缺失 label 自动加入 registry
- 新增到 registry 的 label 按大写写入
- issue front matter 中的 label 也按大写写入

### `modify-metadata`

新增 flag：`--allow-new-label`

默认行为：

- 命令接收到的每个 label 都先做 trim 和大写标准化
- 若任一 label 不存在于 registry，则命令失败

带 `--allow-new-label` 时：

- 允许将缺失 label 自动加入 registry
- 新增到 registry 的 label 按大写写入
- issue front matter 中的 label 也按大写写入

## 统一标准化规则

以下输入都应使用同一套 label 标准化逻辑：

- `new` 命令传入的 `--labels`
- `modify-metadata` 命令传入的 `--labels`
- `list` 和 `search` 过滤条件中的 `--labels`
- `labels remove --label`
- `labels rename --from`
- `labels rename --to`
- `labels sync` 扫描到的 issue labels

标准化规则：

- 去除首尾空白
- 转换为大写

## 查询与展示约束

本版本开始，展示与过滤都以标准化后的大写 label 为准。

- `list` 输出中的 label 使用大写
- `search` 输出中的 label 使用大写
- `show` 输出中的 label 使用大写
- `list --labels ...` 按大写标准化后匹配
- `search --labels ...` 按大写标准化后匹配

这意味着命令对输入大小写应不敏感，但最终持久化和输出都统一为大写。

## 错误语义

所有相关命令采用显式失败，不做静默降级。

- `labels.json` 不存在时，读取类命令按空集合处理
- 需要写入 registry 时，若文件不存在，可自动创建
- `new` 或 `modify-metadata` 使用未注册 label 且未带 `--allow-new-label` 时，命令失败
- `labels remove` 删除不存在的 label 时，命令失败
- `labels remove` 发现该 label 仍被 issue 引用且未带 `--force` 时，命令失败
- `labels rename` 的源 label 不存在时，命令失败
- `labels rename` 的目标 label 已存在且未带 `--force` 时，命令失败
- `labels sync` 遇到历史小写或混合大小写 label 时，不报错，直接统一为大写并回写

## 一致性要求

涉及批量修改 issue 的命令必须保证：

- front matter 中非 label 字段保持不变
- Markdown 正文保持不变
- 对同一 issue 的 label 修改结果可预测且可重复执行

涉及 registry 的写入必须保证：

- label 去重
- label 大写化
- 输出结构稳定

## 兼容与迁移

本版本是对现有 issue 数据的增量升级。

- 旧 issue 中历史遗留的小写或混合大小写 label 不要求人工先修复
- `labels sync` 是推荐的一次性收敛命令
- 即使尚未执行 `labels sync`，写命令和过滤命令也应使用标准化逻辑，避免继续扩散大小写不一致
- `labels.json` 初始可以不存在，由 `labels sync` 或带 `--allow-new-label` 的写命令首次创建
