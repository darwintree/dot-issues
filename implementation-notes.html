v2 Implementation Notes

Notes for the v2 reference rewrite implementation in docs/spec/v2.md.

Design Decisions

  • Reference rewriting lives in a focused utility module instead of inside individual commands.
  • Automatic rewrites scan only Markdown bodies in the active --issue-dir, including archive/.
  • When an issue file moves, inbound links to that issue are rewritten, and links inside the moved issue that point to other known issue files are rebased relative to the moved issue's new location.
  • Bare Obsidian wikilinks are ignored in general, except for moved-file self-links, to avoid global basename guessing.
  • Link paths are emitted with POSIX-style / separators.

Deviations

  • No intentional deviations from the v2 spec.

Tradeoffs

  • The implementation uses a lightweight tokenizer instead of a full Markdown parser. It supports the specified inline links, link titles, angle-bracket destinations, URL-encoded paths, and Obsidian wikilinks.
  • Filesystem rollback is best-effort rather than transaction-grade.

Feedback Loop

  • Independent review found exact .. path validation was too permissive; the validator and tests now cover exact and normalized parent-directory escapes.
  • Manual mutual-link testing found moved-file outgoing links were not rebased; the planner now handles known issue links inside the moved file and tests cover Markdown and Obsidian cases.
  • Markdown inline link titles were promoted from residual risk to supported behavior and are now covered by tests.

Open Questions

  • No open questions.
